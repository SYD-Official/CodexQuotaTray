CodexQuotaTray v{{VERSION}} 使用说明
========================================

请先阅读
----------------------------------------

CodexQuotaTray 是一个面向 Windows 的 Codex 额度显示小工具。程序通过已安装的 Codex 只读接口获取当前账户额度，并只读分析本机会话中的 Token 活动，通过任务栏数字条、系统托盘图标和详情弹窗展示 5 小时额度、每周额度、重置时间及本地 Token 活动。

使用前请注意：

1. 请先安装、登录并启动 Codex 桌面应用，再运行本目录中的 {{FILE_NAME}}。
2. 本工具不会替你启动、登录或控制 Codex，也不会提供 Codex 账号或额外额度。
3. 额度数据来自 Codex 的 account/rateLimits/read 只读接口，与 Codex 当前用量页使用相同口径，并非逐字实时变化。
4. “本地 Token”是本机现存会话文件的只读汇总，不等同于 OpenAI 账户后台的官方统计。
5. 本软件是非官方社区工具，与 OpenAI 没有隶属或背书关系。


一、交付文件
----------------------------------------

主程序：{{FILE_NAME}}
说明文件：CodexQuotaTray-v{{VERSION}}-README.txt

程序为单个 EXE，不需要安装 Visual Studio 或 .NET SDK。设置会自动保存在：

%LOCALAPPDATA%\CodexMeter\settings.ini

通过“检查更新”下载的新版本默认保存在：

%LOCALAPPDATA%\CodexMeter\Updates


二、快速开始
----------------------------------------

1. 启动并登录 Codex 桌面应用。
2. 双击运行 {{FILE_NAME}}。
3. 程序启动后，会在 Windows 托盘区域显示额度圆环，并可在通知区域左侧显示任务栏数字条。
4. 单击数字条或托盘图标，可以打开额度详情页。
5. 右键数字条或托盘图标，可以显示详情、立即刷新或退出程序。

Codex 未运行时，数字条会显示离线状态，程序只等待新的本地快照，不会主动启动 Codex。


三、双额度显示
----------------------------------------

程序不依赖 primary 或 secondary 字段顺序，而是根据窗口时长识别额度：

- 300 分钟：5 小时额度。
- 10080 分钟：每周额度。

如果没有精确的 300 分钟窗口，主显示会使用最短的有效额度窗口；如果没有周额度，小周环和对应详情会自动隐藏。

详情页默认使用主次布局：

- 5 小时额度使用完整主区域，显示额度剩余、时间剩余、使用节奏、重置倒计时和本地重置时间。
- 每周额度使用紧凑区域，显示余额、独立告警颜色和重置倒计时。

可在一级设置中关闭“5小时额度突出显示”，切换为两条尺寸相同的完整额度区域。


四、任务栏数字条与托盘图标
----------------------------------------

任务栏数字条由三部分组成：

1. 左侧大外环表示 5 小时额度余额。
2. 大环内的小环表示 5 小时窗口的时间剩余。
3. 中间大数字显示 5 小时额度百分比，下方显示距重置小时数，例如 3.6H。
4. 右侧周额度小环保持单环，环内显示不带百分号的余额整数。

5 小时与每周额度分别根据自身余额使用告警颜色，互不影响：

- 剩余 21% 以上：使用当前主题色。
- 剩余 11%～20%：变为橙色。
- 剩余不超过 10%：变为红色。

系统托盘图标使用单环显示当前最紧张的额度，悬停提示同时列出 5 小时和每周余额。

任务栏数字条可以在设置中关闭，仅保留系统托盘图标。


五、时间进度与使用节奏
----------------------------------------

时间剩余按照额度窗口时长与重置时间计算。

程序比较“额度剩余”和“时间剩余”来判断使用节奏，并为短时集中使用预留 20 个百分点缓冲：

- 额度消耗比时间进度超前不超过 20 个百分点：显示“节奏正常”。
- 额度消耗比时间进度超前超过 20 个百分点：显示“消耗偏快”。

额度余额本身的橙色和红色告警独立生效，不受节奏提示影响。


六、Token 活动统计
----------------------------------------

Token 活动提供四种范围：

1. 当前 5 小时周期

该视图不是滚动最近 5 小时，而是严格使用当前额度周期：

周期起点 = 5 小时额度重置时间 - 300 分钟

图表固定为 30 个十分钟位置。同一个会话内的连续累计 Token 会先计算正增量，再分配到对应的十分钟桶。周期开始时右侧为空，随着时间和实际活动从左向右推进；没有 Token 活动的时间桶保持空白。

2. 24 小时

显示最近 24 个整点小时的本地 Token 活动，额度变化使用 5 小时额度口径。

3. 7 天

显示最近 7 个自然日的本地 Token 活动，额度变化使用每周额度口径。

4. 30 天

显示最近 30 个自然日的本地 Token 活动，额度变化使用每周额度口径。

鼠标悬停在柱子上，可以查看对应时段的 Token 数量和明确标注口径的额度变化。

额度变化按照对应窗口“剩余百分比的下降量”累计。额度重置补回的部分不会被当作负消耗。某个时段没有足够的前后额度快照时会显示“--”，只有确实计算为零时才显示“0%”。

首次运行本工具时，会回读本机仍然存在的 Codex 历史会话，并非从安装时才开始统计。当前限制为：

- 读取最近 31 天内的本机会话。
- 最多读取最近修改的 300 个会话文件。
- 每个会话读取最后 768KB 范围。
- 删除过的会话、其他电脑上的会话以及本机没有保存的数据不会包含在内。

Token 活动结果会缓存 5 分钟，避免频繁扫描历史文件。


七、任务完成闪烁提醒
----------------------------------------

任务完成提醒默认关闭，可以在“设置 → 更多设置”中开启。

启用后，程序只增量读取 Codex 桌面日志中的状态字段，不读取或显示任务正文：

- turn-complete：把对应任务加入未读集合。
- resumeState=resumed：把已查看任务从未读集合移除。

存在未读完成任务时，托盘图标会在正常额度图标和带蓝色提示效果的图标之间柔和闪烁。蓝色提示是覆盖层，不会遮掉原有额度环及橙色、红色告警。

多个任务会分别跟踪，只有全部任务已读或用户手动清除后才停止闪烁。闪烁时点击任务栏数字条或托盘图标，可以立即清除当前提醒。

提醒状态的检查周期为：

- 空闲时：每 20 秒。
- 存在未读任务时：每 3 秒。
- 未读集合清空后：恢复为每 20 秒。

额度扫描始终保持原有 20 秒周期，不会因为提醒闪烁而提高会话文件扫描频率。

启用提醒时从当前日志末尾开始，不会提醒启用前已经完成的旧任务。关闭提醒开关时会立即停止闪烁并清空临时未读状态。


八、界面与显示设置
----------------------------------------

一级设置包括：

- 任务栏数字条开关。
- 5 小时额度突出显示开关。
- 浅色、深色或跟随系统外观。
- 四套强调色预设。
- 主色与辅色自定义。
- 中文、English 或跟随系统语言。
- 右上角“恢复默认”。
- 左下角“返回首页”。

“更多设置”包括：

- 悬浮窗尺寸。
- 字体尺寸。
- 任务栏数字条尺寸。
- 柔光玻璃开关。
- 柔光玻璃不透明度。
- 任务完成闪烁提醒。
- 版本、作者信息和检查更新。

默认设置：

- 5 小时额度突出显示：开启。
- 任务完成闪烁提醒：关闭。
- 柔光玻璃：开启。
- 柔光玻璃不透明度：40%。

关闭柔光玻璃后，不透明度滑杆会变灰并停止响应。“恢复默认”会同时恢复上述默认值。

程序支持 Per-Monitor V2 DPI。窗口在不同缩放比例的显示器之间移动、Windows 显示缩放变化或任务栏位置变化后，会重新计算尺寸和位置。


九、柔光玻璃说明
----------------------------------------

柔光玻璃使用 Windows 桌面合成器生成动态 Acrylic 背景。滑杆控制玻璃遮罩强度，数值越低，后方桌面内容越明显。

文字使用独立的透明 DirectWrite 灰阶图层绘制，不会随玻璃一起变淡，并避免透明表面出现传统 ClearType 彩边。程序优先使用 DWM 原生圆角；系统不支持相关效果时会保留普通主题背景，不影响额度读取。


十、数据更新与本地目录
----------------------------------------

程序每 20 秒通过已安装的 Codex 只读接口获取一次当前额度，不会逐字刷新。点击右键菜单中的“立即刷新”可以主动读取最新额度。

Codex 数据目录的读取顺序为：

1. 优先使用 CODEX_HOME 环境变量指定的目录。
2. 未设置 CODEX_HOME 时，使用 %USERPROFILE%\.codex。

程序读取 codex 常规额度池中的 5 小时和每周额度，同时识别 gpt-reserve 备用额度。常规额度可用且备用额度尚未消耗时维持原有显示；只有常规额度不可用或备用额度已开始消耗时，才显示备用额度。旧版 sessions 额度快照仅作为当前接口暂时不可用时的兼容兜底；本地 Token 活动仍从 sessions 汇总。


十一、隐私与安全
----------------------------------------

额度刷新会短暂启动已安装的 codex app-server，只发送初始化和 account/rateLimits/read 请求，收到结果后立即结束子进程。身份验证由 Codex 自身处理。本地 Token 活动仍只读访问 sessions 会话文件。

仅当额度响应缺少套餐字段时，程序才会只读打开 auth.json，在内存中解码 ID Token 的载荷，并且只获取 chatgpt_plan_type 套餐字段。

程序不会保存、上传或显示：

- ID Token。
- access token。
- refresh token。
- 邮箱。
- 账户 ID。
- 任务正文。

程序不会自行处理或外传登录凭据。额度刷新由 codex app-server 使用现有 Codex 登录状态完成；只有用户手动点击“检查更新”时，程序才会另外连接 GitHub。


十二、检查更新
----------------------------------------

在“设置 → 更多设置”中点击“检查更新”后，程序会查询：

https://github.com/SYD-Official/CodexQuotaTray

当前已经是最新版时，只在设置页面显示状态。发现新版本时，程序会先询问是否下载。

更新器只接受固定仓库的正式三段式版本、名称匹配的 EXE、GitHub HTTPS 下载地址以及符合发布信息的文件大小和 SHA-256。Draft、Prerelease、异常文件大小、摘要不匹配和非 GitHub 重定向都会被拒绝。

新版本会等待旧进程退出后接管单实例运行。如果自动启动失败，程序会显示完整下载路径，请退出旧版后手动运行新文件。


十三、常见问题
----------------------------------------

1. 为什么显示“Codex 未启动”或离线？

请确认 Codex 桌面应用已经启动并登录。本工具不会自行启动 Codex。首次运行 Codex 或长时间没有活动时，可以让 Codex 完成一次回复，再选择“立即刷新”。

2. 为什么额度没有立刻变化？

程序默认每 20 秒读取一次 Codex 当前额度，因此不是逐字实时更新。也可以右键选择“立即刷新”。

3. 为什么某个历史时段的额度变化显示“--”？

该时段没有足够的前后额度快照，程序无法可靠计算变化。“--”表示数据不足，不代表真实消耗为零。

4. 为什么本地 Token 与账户后台不一致？

本地 Token 只统计这台电脑上仍然存在且仍可读取的会话文件，不能作为 OpenAI 账户后台的官方账单或统计。

5. 为什么 5 小时图表中某些十分钟位置为空？

空白表示对应十分钟内没有识别到 Token 正增量，或者本地会话未保留足够快照。程序不会为了铺满图表而制造数据。

6. 为什么任务栏数字条不是 Windows 原生通知图标？

Windows 没有向普通应用开放可常驻任意文字的任务栏槽位。数字条是由任务栏拥有、不激活且不抢焦点的贴合窗口；托盘圆环仍是标准通知图标。

7. 为什么检查更新失败？

请检查 GitHub、DNS、代理和网络连接是否可用。网络受限时，可以从官方发布地址手动下载。

8. Windows SmartScreen 或杀毒软件为什么提示风险？

程序目前没有商业数字签名，并包含读取本地会话、在任务栏附近显示置顶窗口和手动下载更新等桌面工具常见行为，少数安全软件可能因文件知名度不足产生提示。

请只从可信分享者或官方 GitHub 仓库获取程序，并核对下面列出的文件信息。来源不明或校验不一致时，请不要运行。
